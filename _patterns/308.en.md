> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

Test request validation and a body-only handler.

## Mechanism

Use explicit fixture constructors for partial, invalid and exact shapes instead of erasing all types with the same cast.

## Bad example

```text
Use as unknown as Request in every fixture.
```

## Good example

```text
Label body-only data as partial; label the numeric-id rejection case as intentionally invalid; use exact shape when completeness is what the test asserts.
```

## Why the change matters

The contrast changes the decision procedure and makes its result inspectable.

## Observable expectation

The fixture communicates which constraint is deliberately relaxed.

## Limits

Specific helper API behavior needs version verification; this method concerns test intent, not production type safety.
