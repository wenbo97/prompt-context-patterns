> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

Evaluate a record-normalization tool that should sort records without dropping them.

## Mechanism

Combine grounded examples with applicable invariants such as idempotence, permutation invariance and preservation of the declared record set.

## Bad example

```text
Check only one two-record example, leaving order-dependent behavior on larger inputs undetected.
```

## Good example

```text
Keep that example, add larger and permuted inputs, assert normalize(normalize(x))=normalize(x) and that the expected record set is preserved.
```

## Why the change matters

The oracle tests relationships beyond a small fixed answer set while preserving an independent correctness anchor.

## Observable expectation

A faulty order-dependent or record-dropping implementation fails a named invariant or grounded fixture.

## Limits

Only assert invariants the contract requires; a constant empty result can pass idempotence, so invariants do not replace exact valid/invalid cases.
