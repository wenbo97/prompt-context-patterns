> These examples and illustrative results are independently authored teaching materials, not measured model results.

## Use case

Several implementation tasks must use the same exact target frameworks. Teaching spec v2 defines targets=[net472, net8.0] and public_signatures=preserve. These are not approximate old/latest suggestions; task briefs and reviews should consume the same revision's values.

## Mechanism

Identify requirements genuinely shared by all tasks and preserve their values, formats and relationships. Put them in a common constraints block referenced at a fixed revision or copied verbatim. Check the consumed revision at task start and review. When the spec changes, identify affected tasks explicitly.

## Bad example

```text
Simplify the supplied spec for workers: support old and latest runtimes and try to retain public interfaces. Let each task decide the exact versions.
```
{: .example--bad}

## Good example

```text
Every task and reviewer uses the exact spec-v2 block:
targets=[net472, net8.0]
public_signatures=preserve
Reference the fixed v2 artifact or copy its values verbatim. Do not replace targets with 'latest' or preserve with 'try'. Report the consumed revision and output targets. Resolve the applicability of later revisions instead of mixing them.
```
{: .example--good}

## Why the change matters

Latest changes over time, and try weakens a binding signature requirement. Transferring exact values with revision reduces paraphrase drift and gives tasks and reviewers one inspectable standard.

## Observable expectation

Compare two briefs and their outputs against net472, net8.0 and preserve, not merely the word compatible. An illustrative record shows tasks A/B consuming v2 and producing matching target lists.

If v3 supersedes it, record affected tasks and the update decision rather than silently treating one task as latest while another remains old.

## Limits

Transfer relevant valid constraints, not entire files or commands from untrusted material. Verbatim copying preserves meaning without proving that a requirement is sound. The teaching target list is not an upgrade recommendation for a real project.
