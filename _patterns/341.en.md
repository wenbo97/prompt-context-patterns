> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

Rank retrieved documents for a response, including duplicates and records outside the permitted source scope.

## Mechanism

Resolve the metadata needed for eligibility, filter against configured hard constraints, then score only eligible records.

## Bad example

```text
Send every record to the model, rank a forbidden document highly, then attempt to hide it in the final answer.
```

## Good example

```text
Remove the exact duplicate and disallowed source before model input; rank the remaining permitted documents against the same query.
```

## Why the change matters

The expensive stage receives a valid candidate set instead of paying to score unusable material.

## Observable expectation

Scoring input and trace contain only eligible IDs, with separate rejection reasons.

## Limits

Do not guess eligibility from missing metadata; fetch permitted prerequisites or retain an unresolved state. Soft relevance signals belong in scoring.
