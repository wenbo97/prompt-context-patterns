> 以下示例用于说明方法，不是模型实测结果。

## 使用场景

工具只返回 2,000 条记录中的有界片段，或十二节交付物因响应预算而中断。

## 具体做法

API 记录：原样传递服务签发的游标，并如实报告返回数、已知总数/剩余数及截断/完成状态。生成内容：在完整单元后停止，报告实际完成数、已知总数或总数未知，以及下一单元标签；从该处续写且不重复。两类契约不同：自写单元指针不是 API 令牌。

## 反例

```text
把 API 前 20 条标为完整，编造总数或游标，或生成到 6/12 节时却宣称全部完成。
```

## 改进写法

```text
API：返回 20 条；仅在数据权威时报告总计 2,000、剩余 1,980，标 truncated=true，并将服务返回的不透明游标（例如 C20）原样传回。生成内容：完整写完第六节，报 6/12 和 next_unit=section seven，再从第七节续写且不重放。
```

## 为什么这样改

接收者能分辨部分结果与完整结果，并从正确边界继续，不会把不同游标类型混为一谈。

## 如何验证

每次响应只报告有依据的计数和明确的部分/完成状态；API 令牌或生成单元指针都能续接对应工作。

## 适用边界

不得编造总数或令牌、把部分输出称为完整，也不得把自写单元标签当作服务游标。精确总数可能需要聚合；未知总数必须保持未知。
