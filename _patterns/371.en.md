> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

Implement an MVP that accepts a request, stores it and shows its status.

## Mechanism

Read locked decisions, choose one complete user path with its acceptance check, scaffold that path, evaluate it, then add the next slice.

## Bad example

```text
Implement every data model first and every view next; no user path runs until the end.
```

## Good example

```text
First deliver submit request → persistence → status page for one request type with a real error-path check; evaluate that slice before adding other types.
```

## Why the change matters

The slice exposes integration and contract failures while the change surface is still bounded.

## Observable expectation

One complete user journey is demonstrable with its test and artifact before the second slice starts.

## Limits

A vertical slice is not license to invent product behavior; use the existing spec and keep shared architecture decisions intact.
