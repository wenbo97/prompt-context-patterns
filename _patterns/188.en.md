> These examples and illustrative results are independently authored teaching materials, not measured model results.

## Use case

Rename published pattern ID100 in both languages while old slugs/anchors have external references. Stable identity determines canonical location; display changes should not retarget unrelated content or unexplained 404.

## Mechanism

Separate identity/labels, preserve IDs and map necessary retired slugs to canonical identity/language. Check merge targets, fragments, loops/chains and no-JS entries. Distinguish HTTP redirects, client transfers and readable compatibility rather than calling all 301.

## Bad example

```text
Reuse ID100 for another method, delete old entries and claim server 301 from client script alone.
```
{: .example--bad}

## Good example

```text
Keep teaching ID100, update bilingual labels and map old slugs/fragments to the same language-aware method. Explicit merges/removal reasons retain identities. Verify valid targets/no cycles/no-JS links and report actual transfer type without assuming search-signal migration.
```
{: .example--good}

## Why the change matters

Stable identity preserves referenced objects through editorial changes. Explicit mappings retain language/entry continuity and actual redirect semantics.

## Observable expectation

Old/new entries resolve ID100, with Chinese fragments reaching Chinese or explicit compatibility. Deliberate cycles fail.

Client success proves neither HTTP301 nor no-JS/search transfer; no live route changes occur.

## Limits

Stable identity does not permanently retain bad content; merges/removals need decisions. Hosting capabilities and post-release checks determine migration effects. Provenance remains unconfirmed.
