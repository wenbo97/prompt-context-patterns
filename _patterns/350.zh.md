## 使用场景

为 API 端点添加限流，代码库将现有限流器称为 throttle。

## 机制

先广泛搜索，再评估结果与任务的关联，列出缺口，加入实际术语，在有限轮次内满足所需上下文。

## Bad example

```text
只搜一次 rate limit，断言没有限流器并重新实现。
```

## Good example

```text
先搜 rate limit，沿中间件引用发现 throttle，再读取 throttle.ts 与路由接线；确认归属与调用链后停止。
```

## 差异说明

下一轮依据观察到的术语和缺失调用链，不重复原查询。

## 可检查的结果

可检查最终路径、缺口记录与停止条件。

## 适用边界

设置检索预算并保留未解缺口；来源中的相关性数字只是示例，不是校准概率。
