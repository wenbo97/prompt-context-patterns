> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

Repeated analysis requests share a policy and document, but a request ID is inserted ahead of both.

## Mechanism

Trace every assembly input; order stable global, session and turn content according to the host contract, place the cache boundary before the unique tail, and compare real payloads plus cache metrics.

## Bad example

```text
Put a fresh UUID at the beginning of every request and assume adding a cache marker guarantees reuse.
```

## Good example

```text
Keep the shared policy and document byte-stable, put the UUID and question after them, then check whether a second eligible request actually reads the shared prefix.
```

## Why the change matters

The reusable region is defined by actual rendered inputs rather than semantic similarity or marker presence.

## Observable expectation

Rendered overlap, scope/eligibility and recorded cache reads can be checked.

## Limits

Cache key, ordering, eligibility, TTL and readiness are provider-specific. Preserve authority, freshness, privacy and reviewer independence before optimizing reuse; a zero read has causes beyond byte drift. No fixed idle window or pricing promise is implied.
