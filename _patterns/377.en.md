> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

Design review adds an accessibility obligation to a plan that engineering will revise.

## Mechanism

Separate the current implementation plan from immutable review history. Record accepted obligations with their source revision; a new phase adds a new checkpoint instead of replaying old replacements.

## Bad example

```text
Rewrite the plan for engineering. Keep only the latest reviewer's suggestions.
```

## Good example

```text
Revise the plan for engineering. Retain the accepted keyboard-access requirement from design review R1. Record new amendments under R2, leaving the R1 source and decision unchanged. If a requirement conflicts, identify it as unresolved rather than silently dropping it.
```

## Why the change matters

Later context compression no longer discards earlier commitments or misattributes their source.

## Observable expectation

The revised plan still includes keyboard access; both R1 and R2 amendment records retain their actual decisions.

## Limits

History is evidence rather than permanent authority. Explicit later user decisions can supersede an obligation and must be recorded.
