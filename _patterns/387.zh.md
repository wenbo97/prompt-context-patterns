> 以下为独立教学构造，未声称是实际模型输出或已测得的性能。

## 使用场景

团队声称 SDK 入门比同类产品快，但各家的快速开始流程要求不同，结束位置也不相同。

## 机制

明确目标开发者、文档中的起点和首次有用结果。逐项记录本产品及查阅到的同类产品，包括操作步骤、时间、证据类型、旅程边界、设计选择和来源。把人工上手时间与自动执行时间分开。只有起止边界一致时才比较时长；否则说明差异，转而比较设计选择。估算与未知都要标记，不能把文档未提到某步骤当作耗时为零。完成比较后先请用户选择目标，再将答案带入后续审查。

## Bad example

```text
同类 A 的预热演示两分钟就结束，同类 B 没写耗时。我们的全新安装需要五分钟，所以结论写 A 快 2.5 倍，B 完全没有安装等待。
```

## Good example

```text
对使用 Python 应用开发的目标人群，从干净安装开始，比较各家到首次评估用户自己函数的路径。注明 A 的演示使用脚手架、结果终点不同；B 的耗时未知；本产品的全新安装时间只是估算。说明最接近同类产品的设计选择并引用具体步骤，在修改计划之前询问用户适合哪个目标。
```

## 差异说明

这样既能围绕特定开发者提出建议，也能保留文档事实、估算依据和旅程之间的可比边界。

## 可检查的结果

审查指出最相关的同类产品及原因，不给起止边界不同的流程做数字排名，不替未知数据编值，并在实施变更前记录用户选定的目标。

## 适用边界

文档流程和审阅者估算不能证明实际观察到的上手时间，也不能证明产品有效。数字比较必须有相同起点与结果边界；同类文档没提及某步骤，不代表该步骤不存在。
