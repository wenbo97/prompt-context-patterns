> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

A review skill demonstrates PostgreSQL parameter binding, while its host expands positional argument markers in the skill body.

## Mechanism

Inspect the rendered invocation with representative arguments. Protect colliding literals with a documented non-expanding reference or escape mechanism; if neither exists, explain binding in prose rather than corrupt the driver syntax.

## Bad example

```text
Put SELECT * FROM users WHERE id = $1 in the expanding skill body and assume the example survives /review alice unchanged.
```

## Good example

```text
Keep the PostgreSQL example in a verified non-expanding reference, or use the host's documented escaping. Render /review alice and a no-argument invocation; compare the query placeholder and parameter array with the source. If protection is unavailable, describe PostgreSQL binding in prose.
```

## Why the change matters

The same characters can be meaningful to two interpreters; a valid SQL example may be transformed before the model sees it.

## Observable expectation

Both rendered invocations retain the intended parameter-binding semantics, or the skill explicitly uses a prose fallback.

## Limits

Host preprocessing is a source-observed warning, not a universal behavior. Preserve the actual driver's syntax; '?' is not a universal PostgreSQL replacement. Do not assume a reference file is exempt without testing the host's expansion boundary.
