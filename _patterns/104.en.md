> These examples and illustrative results are independently authored teaching materials, not measured model results.

## Use case

Browser checks need a test service and an approved helper. Teaching help defines service command/port/readiness timeout/test command. Unknown scripts are not trusted merely because they accept --help. Use a supported interface rather than reimplementing lifecycle in prose.

## Mechanism

Verify origin/version/allowed effects/fit. For trusted authorized helpers inspect actual help, map supported parameters, execute and inspect startup/test/cleanup separately. Read necessary implementation when the interface is insufficient or fails; black-box use does not prohibit questioning or justify guessed flags.

## Bad example

```text
Rebuild lifecycle from memory, pass invented flags or execute unknown --help before review; exit 0 means reliable cleanup.
```
{: .example--bad}

## Good example

```text
Verify the teaching helper's version/purpose, inspect actual help and use documented service/port/timeout/test arguments. Retain readiness, exit and owned-cleanup evidence. Inspect relevant source on gaps/failure rather than blindly editing. Review untrusted executables before even --help.
```
{: .example--good}

## Why the change matters

A stable interface offloads deterministic lifecycle, with explicit trust/capability boundaries rather than unsupported reliability promises.

## Observable expectation

Trace parameters to help and test/cleanup outcomes separately. Missing flags are interface gaps; successful cleanup does not erase failure.

Help/exit 0 alone proves no all-path guarantee. No frozen helper executes here.

## Limits

Source black-box advice applies only to trusted, fitting authorized helpers. Effects may include children/network/files and need inspection. Large implementation size does not forbid necessary reads.
