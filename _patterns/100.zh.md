> 以下示例与示意结果由本站编写，用于说明方法，不是模型实测结果。

## 使用场景

一个云发布 Skill 支持 AWS 和 Azure，但当前请求已明确是 AWS 的只读发布准备。教学目录含入口 `SKILL.md` 和 `references/aws.md`、`references/azure.md`；AWS 文件说明准备时核对 region 与 role，Azure 文件处理订阅和资源组。你不需要先加载两个完整分支。

## 具体做法

入口保留所有分支共用的目标、授权边界和完成条件，再给每个分支写明确读取触发。已知 AWS 时读取 AWS 指南，按其约定准备材料；供应商未知时只解决这个选择。引用相对路径以 Skill 根目录为基准。必要资料缺失就报告该分支无法准备，不用另一份指南填补。

## 反例

```text
为上述 AWS 只读准备任务，先读取 AWS 和 Azure 的所有完整资料，然后从中选择看起来适用的步骤。授权规则也可以只放在某个参考文件中。
```
{: .example--bad}

## 改进写法

```text
在入口保留共同规则：本次只准备方案，不提交发布；完成条件是列出候选配置和缺失输入。已知供应商为 AWS，只读取相对 Skill 根目录的 references/aws.md，核对其中 region 和 role 的要求。Azure 分支仅在任务选择 Azure 时读取 references/azure.md。供应商未知先澄清，选中分支文件缺失就报告缺失，不猜平台步骤。
```
{: .example--good}

## 为什么这样改

明确触发把资料加载与真实任务选择相连，减少无关指南混入操作。共同边界留在入口，避免未选分支藏着所有任务都必须遵守的规则。按需读取仍是执行过程，不能只写路径却从未读取。

## 如何验证

示意读取记录：供应商 AWS → 读取 aws.md → 报告 region/role 是否已提供 → 交付准备方案，未提交；azure.md 因未选 Azure 不读取。

检查真实读取记录与分支一致，缺文件时留下缺失状态。若 AWS 流程混入订阅/资源组要求，或没读指南就声称完成，都需要核查。

## 适用边界

资料仍消耗上下文，宿主加载方式和实际成本各不相同。来源中的字数、行数或节省比例不是本篇效果测量；不要承诺无限上下文。参考材料应容易从入口到达，避免必须经过多层未读文件才能发现关键规则。
