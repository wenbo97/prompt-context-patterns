> 以下示例用于说明方法，不是模型实测结果。

## 使用场景

一个云发布 Skill 同时支持 AWS 和 Azure，但一次任务只涉及其中一家。

## 具体做法

入口保留共同规则和平台选择步骤；确定平台后，只读取该平台的详细指南。

## 反例

```text
每次发布请求都加载两个供应商的完整指南。
```

## 改进写法

```text
入口含共同验证和供应商选择。AWS 读取 references/aws.md；Azure 读取 references/azure.md。授权边界保留内联；供应商未知时先澄清再加载分支。
```

## 为什么这样改

按需读取能避免无关资料占用上下文，同时保持共同的授权和验证规则始终可见。

## 如何验证

AWS 任务读取 AWS 指南，且能说明为何无需读取 Azure 指南。

## 适用边界

读取资料仍会占用上下文，具体成本由工具决定。所有任务都必须遵守的规则不能藏在未加载的分支中。
