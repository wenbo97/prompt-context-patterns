> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

Coordinate design, implementation and review for one feature.

## Mechanism

State transitions require evidence rather than a worker's success label.

## Bad example

```text
Ask agents to handle development and report whatever they finish.
```

## Good example

```text
States: designed → implemented → reviewed. Each worker returns completed_state, artifact_path, revision and unresolved_items. Coordinator validates the artifact before moving state; failed review keeps the task implemented.
```

## Why the change matters

State transitions require evidence rather than a worker's success label.

## Observable expectation

A missing or failed review cannot advance to reviewed.

## Limits

Enforce state updates atomically if multiple coordinators can write.
