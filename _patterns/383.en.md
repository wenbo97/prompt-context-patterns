> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

A browser agent should keep read access after its write permission is withdrawn.

## Mechanism

Resolve the same principal identity, revoke its previous broader session, issue the narrower grant and verify the old credential is rejected. Creating a second principal does not revoke the first.

## Bad example

```text
Give agent audit-bot a new read-only token. Leave its existing token alone.
```

## Good example

```text
Reduce audit-bot to read-only under the same principal identity. Revoke its prior write-capable session, issue the narrower grant and verify the old token cannot write. Record the reconnect requirement and the resulting scopes.
```

## Why the change matters

The new token no longer coexists with an active broader token for the same agent.

## Observable expectation

The new session permits reads, denies writes, and the previous credential is rejected.

## Limits

Prompt text cannot enforce permissions. The service must implement revocation and scope checks; browser JavaScript access can exceed apparently read-only named commands.
