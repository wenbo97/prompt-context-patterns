## 使用场景

你要为发布记录生成查询，已有准确 schema，但“活动阻断发布”不是凭名字就能推断的领域术语。教学 PostgreSQL schema v2 为 `deployments(id, is_deleted, kind)`；活动表示 is_deleted=false，阻断 kind 为 halt 或 block_all。教学行是 `(1,false,halt)`、`(2,false,allow)`、`(3,true,block_all)`。

## 具体做法

在生成查询的步骤附近提供字段名、取值含义、版本和适用表。先确认材料与目标 schema 相符，再把领域条件翻译成查询条件；不补造看起来合理的 status 字段。schema 不同或含义缺失时列出差异，先解决必要事实。

## 反例

```text
根据上述 schema 与教学行查询活动阻断发布。使用你认为合适的 status 字段和值，不必核对 schema 版本。
```

## 改进写法

```text
使用上面的 PostgreSQL deployments schema v2。活动条件是 is_deleted=false；阻断 kind 为 halt 或 block_all。查询 id，必须使用给定字段和值，并说明条件如何对应领域定义。如果目标 schema 与 v2 不同，先报告差异，不猜一个 status 字段。用三条教学行检查过滤结果。
```
{: .example--good}

## 为什么这样改

抽象业务词可能被映射到不存在的列或错误枚举。把短领域事实放在使用处，能说明每个过滤条件来自哪里，并给版本不匹配设置可见的失败路径。

## 如何验证

示意查询为 `SELECT id FROM deployments WHERE is_deleted = false AND kind IN ('halt','block_all');`，教学结果应只有 id=1。id=2 不阻断，id=3 已删除。

检查列名来自 v2、过滤逻辑匹配三行数据；出现 status、误收已删除记录或没有报告 schema 差异都不通过。此结果是静态教学推导，不是数据库执行记录。

## 适用边界

少量稳定事实适合内嵌；庞大或频繁变化的资料应使用版本化参考文件。领域定义可能过期，查询正确性还依赖真实数据与数据库方言。原文未确认，不能把教学 schema 当真实发布系统。
