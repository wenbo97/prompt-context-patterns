> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

Final review finds three related null-handling defects in one module.

## Mechanism

One owner can resolve interacting edits without competing patches.

## Bad example

```text
Spawn one fixer per finding to edit the same file concurrently.
```

## Good example

```text
Give one fixer the complete finding list, fixed base revision and owned module. Require evidence for each fix and one combined validation run; review the resulting fix diff against all three findings.
```

## Why the change matters

One owner can resolve interacting edits without competing patches.

## Observable expectation

The fix report maps every finding to a change and covering check.

## Limits

Separate truly independent ownership areas when batching would hide unrelated risks.
