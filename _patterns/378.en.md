> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

Both the baseline and a new prompt overlay solve every fixture correctly.

## Mechanism

Keep behavior acceptance and matched ON/OFF comparison as separate outcomes. Preserve the same task, runtime and measurement definition; report saturated baselines, regressions and incomplete comparisons explicitly.

## Bad example

```text
The overlay arm solved all cases. Conclude that adding this instruction improves correctness by 20%.
```

## Good example

```text
Run the same declared fixture in baseline and overlay arms. Report behavior acceptance for each arm, then the complete comparative measurements. If both solve every case, mark the baseline saturated and no demonstrated marginal benefit. Preserve any increased resource cost rather than folding it into a pass.
```

## Why the change matters

Successful execution establishes the behavior observed, while causal improvement requires a discriminating comparison.

## Observable expectation

The report shows behavior passing in both arms and no measured correctness improvement; any cost regression remains visible.

## Limits

An ON/OFF comparison still needs controlled conditions and an adequate sampling design. A saturated fixture cannot distinguish a beneficial intervention; a free harness test verifies the instrument rather than live model efficacy. Detector validity can be checked against labeled or shadow observations; intervention benefit requires a controlled outcome comparison. A detection-quality result alone does not establish that acting on the signal helps.
