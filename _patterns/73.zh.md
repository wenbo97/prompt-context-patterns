> 以下为独立教学构造，未声称是实际模型输出或已测得的性能。

## 使用场景

发布工具接受版本请求后超时。

## 机制

稳定操作身份防止模糊超时造成重复效果。

## Bad example

```text
反复调用 deploy 直到返回成功。
```

## Good example

```text
提交前保存版本键 r42；超时后查询 r42 状态。仅用同一键经幂等 API 重提；记录的健康检查通过后才从 submitted 进入 healthy。
```

## 差异说明

稳定操作身份防止模糊超时造成重复效果。

## 可检查的结果

r42 只创建一个版本，状态反映实际检查。

## 适用边界

API 必须实现幂等与并发控制；提示词不能替代它们。  区分操作重试键与源实体自然键。重复实体同步需要租户范围内的目标唯一性或原生 upsert；自然键本身不能解决不确定写入交付。先对账未知结果，再复用由接收端执行的操作身份。对于用户问题，只重试传输层已确认展示前失败的调用；可能已经展示的问题须等待实际答复。无答复、预选项或时间流逝均不等于同意。
