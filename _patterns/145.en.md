> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

A patch may be declared passing only after its covering check runs.

## Mechanism

The named rule binds a success claim to evidence rather than rhetorical strength.

## Bad example

```text
Try to verify the patch if there is time.
```

## Good example

```text
Verification rule: before claiming this patch passes, run the agreed covering check and inspect its result. If execution is unavailable, report unverified plus the blocked check; never replace observed output with confidence.
```

## Why the change matters

The named rule binds a success claim to evidence rather than rhetorical strength.

## Observable expectation

No passing claim appears without the matching recorded check.

## Limits

Respect higher-priority instructions and agreed task scope; verification rules need relevant checks.
