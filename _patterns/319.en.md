> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

Test an order module with database and third-party payments.

## Mechanism

Distinguish in-process, local-substitutable, remote-owned and true external dependencies before choosing real stand-ins, ports or mocks.

## Bad example

```text
Mock every internal function to make tests fast.
```

## Good example

```text
Use a local database stand-in through the module interface; inject only the external payment port and verify observed outcomes.
```

## Why the change matters

The contrast changes the decision procedure and makes its result inspectable.

## Observable expectation

The tested boundary reflects ownership and real failure surfaces.

## Limits

A stand-in may differ from production; contract/integration checks remain necessary.
