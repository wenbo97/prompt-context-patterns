> 以下为独立教学构造，未声称是实际模型输出或已测得的性能。

## 使用场景

审核有大量已记录破坏性变化的框架升级。

## 机制

可达性区分实际适用风险与通用迁移文档。

## Bad example

```text
把所有全局破坏性变化列为项目已确认缺陷。
```

## Good example

```text
列导入 API 与已追踪调用方，和版本变化求交集。每个可达变化展示本地路径及所需检查；未观察运行时加载 API 列为覆盖缺口。
```

## 差异说明

可达性区分实际适用风险与通用迁移文档。

## 可检查的结果

每个本地问题有代码路径，或明确暂定的动态假设。

## 适用边界

静态可达性可能漏掉反射和插件；不能只凭 imports 声称完全不存在。
