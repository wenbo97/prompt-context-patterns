> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

Refactor a file containing a fixed vendor block.

## Mechanism

Preserve original bytes and identity, edit only the intended projection, then reconstruct and verify protected content and changed surroundings before applying.

## Bad example

```text
Show all bytes with a vague do-not-edit warning, or compile a working file after replacing its logic with comments.
```

## Good example

```text
Use a separate editing view with stable vendor-block sentinel, retain the original, reconstruct the patch and verify the protected block digest before applying it.
```

## Why the change matters

The procedure preserves the stated identity or evidence boundary instead of allowing a plausible shortcut to stand in for it.

## Observable expectation

The edit contract can check both intended changes and preservation.

## Limits

The observed hook modifies working files in place and uses short/fuzzy IDs; that implementation is not a security boundary or guaranteed collision-free recovery.
