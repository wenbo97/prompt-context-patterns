> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

A delayed refresh and a save both update the same editor document.

## Mechanism

Name the caller boundary and invariant; draw a combined schedule, pause at relevant awaits, exercise both completion orders, then inspect a fresh consumer. Exclude an order only with a concrete prevention mechanism.

## Bad example

```text
Review refresh and save separately. Their final assignments are atomic, so conclude the editor is race-free.
```

## Good example

```text
Review refresh and save together. Invariant: a delayed refresh must not overwrite a newer saved document. Pause refresh before its result is applied, complete save, resume refresh, then read the document from a fresh consumer. Also exercise the reverse completion order. Record the version checks or cancellation mechanism that prevents a violating schedule, and test it with controlled gates.
```

## Why the change matters

Atomic assignments do not establish ordering across awaits; the combined schedule exposes stale-result overwrites.

## Observable expectation

The review records both relevant orders and checks the fresh document against the stated invariant.

## Limits

This covers the named shared-state boundaries, not every possible interleaving. Controlled schedules require suitable instrumentation and cannot replace production contract evidence.
