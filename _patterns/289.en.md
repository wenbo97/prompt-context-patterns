> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

Fix sessions remaining active after a password change.

## Mechanism

State the invalidation behavior, reproduce it with a failing oracle, implement the change and verify that the same oracle plus relevant regressions pass.

## Bad example

```text
Review and improve authentication with no named failing behavior or check.
```

## Good example

```text
Specify old-session rejection after password change; demonstrate failure first; implement invalidation; run that check and relevant session regressions.
```

## Why the change matters

The loop terminates on evidence of the desired behavior rather than a narrative of activity.

## Observable expectation

The verification records show the stated defect before the change and the intended behavior after it.

## Limits

The oracle must detect the defect; source tie-order examples checking only scores do not establish tied-identity order.
