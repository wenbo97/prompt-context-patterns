> 以下示例用于说明方法，不是模型实测结果。

## 使用场景

编写一个用于 PR 代码审查的 Skill，让支持 YAML frontmatter 的 Agent 能识别它。

## 具体做法

在文件开头写明 Skill 名称，并在 description 中说明什么请求应触发它。

## 反例

```text
name: helper
description: 帮助处理事情
```

## 改进写法

```text
---
name: pr-review
description: 用户要求评审 PR diff 时，检查具体正确性缺陷。
---
```

## 为什么这样改

“帮助处理事情”无法区分任务。明确写出 PR diff 审查，可以让工具区分代码审查和代码实现请求。

## 如何验证

确认工具能解析 name 和 description；分别用审查请求和实现请求检查是否正确触发。

## 适用边界

只使用运行工具支持的字段。元信息用于描述和发现 Skill，本身不能强制执行工具权限。
