> These examples and illustrative results are independently authored teaching materials, not measured model results.

## Use case

Create a ticket in service S, but current discovery returns other services only. Teaching title/body/project exist and draft preparation is permitted. Do not invent create_issue or substitute another destination.

## Mechanism

Verify inventory/search scope/connection and state the current gap without permanent-absence claims. Use documented scoped alternatives such as a draft/configuration path, labelled unsubmitted. No actual creation/readback means no fabricated external ID/success.

## Bad example

```text
Invent S's slug/ID123 or create elsewhere and call the user's target complete.
```
{: .example--bad}

## Good example

```text
Record no discovered S-create action. Prepare the permitted target-specific draft without guessed calls/substitute services, retaining not submitted. Explain verified setup/manual alternatives. No actual target confirmation means no ID. Rediscover changes rather than relying on frozen unavailability forever.
```
{: .example--good}

## Why the change matters

Fallback preserves preparation value without fabricating effects; identity/status show which work remains unsupported.

## Observable expectation

The fixture delivers an S draft, not ID or another-service action. Inspect explicit discovery scope. Similarly HTML delivery with unavailable PNG capture leaves export pending rather than generated.

No external ticket or image is created here.

## Limits

Search may be incomplete, so undiscovered differs from unsupported. Frozen examples establish no current capability. Alternatives retain purpose/authorization.
