## Use case

A streaming file-write call returns a parsed object while generation stopped at the output limit.

## Mechanism

Accumulate the complete turn, inspect its termination state, reject refusal or cutoff, strictly parse available raw input, validate the contract, then apply the authorized effect.

## Bad example

```text
Write the parsed file body immediately because the object has the required path and contents fields.
```

## Good example

```text
When the turn ended by cutoff, keep the destination unchanged, record incomplete generation, and retry under a bounded policy before any write.
```

## Why the change matters

A tolerant parse can produce a plausible object without proving the intended input was complete.

## Observable expectation

The final stop state, validation result and absence of premature effects can be checked.

## Limits

Schema validity alone cannot detect every truncated-but-valid string. SDK parsing and streaming contracts vary; client gates cannot undo server-side effects already performed.
