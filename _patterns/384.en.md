> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

An untrusted application prints a passing test summary while the evaluator checks an authorization repair.

## Mechanism

Keep the behavioral oracle and authenticated evidence outside the target-controlled process. Bind it to the tested snapshot and assertion; retain the project runner result as self-reported unless its completion is independently witnessed.

## Bad example

```text
The application printed all tests passed and exited zero. Mark the authorization repair verified.
```

## Good example

```text
Assess the authorization repair on snapshot S2. Use an isolated external verifier for the unchanged cross-tenant denial assertion and legitimate-access control. Record its authenticated results separately from the application's test summary. Without the external witness, keep runtime assurance unconfirmed; do not upgrade a printed pass to proof.
```

## Why the change matters

The target cannot gain stronger assurance merely by controlling its own reporter output.

## Observable expectation

The report separates externally witnessed assertions from self-reported project-test completion and identifies any missing witness.

## Limits

A second process alone is not a trust boundary when the target can alter its oracle or evidence. This mechanism requires isolation and provenance; it does not authenticate every project test.
