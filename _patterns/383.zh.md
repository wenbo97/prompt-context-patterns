> 以下示例用于说明方法，不是模型实测结果。

## 使用场景

浏览器 Agent 撤销写权限后，还需保留读取能力。

## 具体做法

定位同一主体，撤销先前宽权限会话，再签发较窄授权，并验证旧凭据被拒绝。新建第二个主体不会撤销第一个。

## 反例

```text
为 audit-bot 再发一个只读令牌，原令牌保持原样。
```

## 改进写法

```text
在同一主体身份下，把 audit-bot 降为只读。撤销原写权限会话，签发较窄授权，核对旧令牌不能再写入。记录重新连接要求与最终权限范围。
```

## 为什么这样改

同一个 Agent 不会同时保留新的窄授权和有效的旧宽授权。

## 如何验证

新会话可以读、不能写，旧凭据被拒绝。

## 适用边界

提示词不能强制权限。服务端必须执行撤销和范围检查；浏览器 JavaScript 能力可能超过名称看似只读的命令。
