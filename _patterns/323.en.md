> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

A multi-page product has shared color, typography and spacing rules, while checkout needs a documented exception.

## Mechanism

Generate a project MASTER file for shared rules; create a page-specific file containing only deviations; when implementing a named page, look up that page file first and apply documented overrides, otherwise use the master. Make field-level merge or replacement semantics explicit.

## Bad example

```text
Copy the entire master into each page file, then edit copies independently so shared rules drift and no one knows which source wins.
```

## Good example

```text
Teaching fixture: MASTER.md defines button.padding=12 and text.color=#0F172A. pages/checkout.md records only button.padding=16. Declare field-level overlay: named page values override the master, every unmentioned field inherits, and a missing page file uses the master. Load both for checkout and verify padding=16 with the inherited text color.
```

## Why the change matters

Durable shared defaults and local exceptions remain discoverable across sessions without silently conflating precedence.

## Observable expectation

A reviewer can locate the project baseline, page-specific delta and stated precedence used for that page.

## Limits

The source proposes page overrides but leaves field-level merge versus replacement underspecified; define semantics before relying on partial files. This pattern does not validate token values or guarantee runtime retrieval.
