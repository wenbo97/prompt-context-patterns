> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

Turn an order-management description into relational tables.

## Mechanism

The intermediate representation exposes assumptions before code hardens them.

## Bad example

```text
Create all necessary tables for orders and make them correct.
```

## Good example

```text
First list Customer, Order and OrderLine with cardinalities. State whether discounts apply per line or per order; keep that unresolved if unspecified. Derive keys and creation dependencies from the confirmed model, then generate DDL.
```

## Why the change matters

The intermediate representation exposes assumptions before code hardens them.

## Observable expectation

Each foreign key traces to a stated relationship; undecided discount scope remains visible.

## Limits

Do not impose an arbitrary table-count cap or present inferred business rules as confirmed.
