> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

Add one percentage-discount calculation to an existing service.

## Mechanism

Implement the actual calculation with its required input rules, and introduce strategy/configuration layers only when a real use case needs them.

## Bad example

```text
Add multiple strategy classes, plugin configuration and notifications for one requested percentage calculation.
```

## Good example

```text
Add a small percentage calculation with required validation; leave other discount modes outside this task.
```

## Why the change matters

The implementation complexity has a traceable reason.

## Observable expectation

Every introduced feature or abstraction corresponds to a present requirement.

## Limits

Necessary safety, validation and existing architectural contracts still apply; fewer lines alone is not success.
