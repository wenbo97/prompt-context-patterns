> 以下为独立教学构造，未声称是实际模型输出或已测得的性能。

## 使用场景

修复一个 React 确认对话框：关闭后键盘焦点没有返回触发按钮。

## 机制

选择最小适用搜索模式，用2至5个词表达一个意图；随后核对结果的领域/类别以及首条内容的身份和适用性。必要时只重试一次，标明回退结果，并且不保存未经核验的输出。

## Bad example

```text
假设目录用例：同一对话框问题在宽泛搜索中命中 style-pricing-palette；仅因它提到 React 就接受，将配色保存为修复方案，未检查键盘行为。
```

## Good example

```text
假设目录用例：在 UX 模式搜索“对话框 键盘 焦点”，确认 ux-focus-return 是恢复触发按钮焦点的可访问性指导，且平台范围适用。只有需要实现细节时才单独查询 React。保存已核验的指导；若有界重试仍无合适匹配，标明回退，不保留未经核验的结果。
```

## 差异说明

简短查询仍可能命中错误领域；同时核对类别与条目适用性，可在错误变成持久指南前发现问题。

## 可检查的结果

可以检查所选模式、查询词、首条结果、重试/回退和保存决策。

## 适用边界

此契约不验证目录事实准确性，也不保证设计质量。搜索失败不代表可以编造结果；仍可能需要人工复核。 2至5个查询词与只重试一次是该来源给出的有界策略示例，不是经验证的普遍最优值；应结合任务、目录内容与新鲜度判断其适用性。
