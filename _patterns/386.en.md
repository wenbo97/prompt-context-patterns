## Use case

An investigation acquires a scoped lock, then another session replaces it at the same path.

## Mechanism

Retain the acquisition token. On termination, atomically compare ownership and release only a matching lock; preserve a replacement and report cleanup failure.

## Bad example

```text
When the investigation ends, delete the lock file at its known path.
```

## Good example

```text
Retain the lock token returned when this investigation acquired it. On completion or abort, call compare-and-release with that token. If ownership changed, preserve the replacement. Report cleanup errors; never fall back to deleting the path.
```

## Why the change matters

A pathname can be reused; the ownership token distinguishes this operation's state from a later replacement.

## Observable expectation

A matching owned lock is released; a replacement at the same path remains intact.

## Limits

Requires an atomic ownership-aware helper. Abrupt process death may prevent cleanup and needs explicit recovery.
