> These examples and illustrative results are independently authored teaching materials, not measured model results.

## Use case

Document existing order behavior while renaming the display heading from Reject empty order to Empty-order validation. Teaching code shows Checkout synchronously calling OrderService.validateEmptyOrder, which throws EMPTY for empty lines; OrderServiceTests.rejectEmptyOrder covers an empty array. Another asynchronous consumer is unread.

## Mechanism

Inspect enforcement and callers, using the verified enforcement point as stable identity and storing the editable label, entities and existing test separately. A heading rename updates one record rather than creating a duplicate. Record dependencies/triggers only from traceable calls; unknown enforcement/tests and unread async paths remain unresolved.

## Bad example

```text
Use the display title as ID, create a new requirement after renaming and discard the old test link. Infer all asynchronous paths enforce the rule from a nearby worker filename.
```
{: .example--bad}

## Good example

```text
Record stable id=OrderService.validateEmptyOrder from the supplied inspected code, with real enforcement/test locations and entity Order. Rename the label to Empty-order validation under the same ID, retaining its test. Checkout's synchronous call is evidenced; the unread async consumer stays unresolved. Do not infer cross-module dependencies or universal coverage. Return the delta and open relationships.
```
{: .example--good}

## Why the change matters

Separating identity from display text preserves source/test continuity through editorial changes. Traceable relationships also prevent a local record from being presented as universal enforcement.

## Observable expectation

An illustrative delta updates one ID's label while preserving enforcement/test links; the async consumer remains unconfirmed. Check for no duplicate requirement, lost link or enforcement claim on unread paths.

A source pointer establishes existence; an executed test pass needs its own record. This example does not equate a test's presence with success.

## Limits

Function moves/renames may require explicit identity migration. Extracted behavior describes implementation rather than proving the business rule sound. One caller and test do not establish all-path coverage.
