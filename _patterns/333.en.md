> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

Document an existing order handler, then rename the human-readable “reject empty order” heading in a later revision.

## Mechanism

Inspect implementation and callers; record a stable requirement ID, enforcing function, entities and any existing test. Rename the label while retaining the ID; omit unsupported metadata rather than inventing an enforcement point.

## Bad example

```text
Use the heading text as identity, so the rename creates a new requirement and loses the previous test link; invent a dependency from a nearby file name.
```

## Good example

```text
Keep OrderService.validateEmptyOrder as the same ID across the heading rename, cite its enforcing function and rejection test, and mark the unread asynchronous consumer as unresolved.
```

## Why the change matters

Behavior identity and source evidence remain attached across editorial changes, while inference gaps stay visible.

## Observable expectation

The delta updates one existing behavior and preserves its source/test links; unresolved relationships are listed separately.

## Limits

A source pointer proves a location, not universal enforcement or normative correctness. Function moves need an explicit identity migration, and one caller or test cannot establish all paths.
