> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

Verify a frontend change with types, browser accessibility and mutation checks.

## Mechanism

Name each check target, lifecycle phase and cost budget; reuse existing evidence rather than running the same unchanged suite twice.

## Bad example

```text
Run every full-repository check after every keystroke.
```

## Good example

```text
Run affected types/lint after edits, related tests at task end and costly browser/mutation checks at preview or CI, each with its declared result.
```

## Why the change matters

The contract names which evidence may be reused and which decision remains unresolved, so the result can be checked.

## Observable expectation

Fast iteration retains an inspectable final quality gate.

## Limits

Cost estimates and source tool commands need local measurement/version verification; moving a check must not silently remove it.
