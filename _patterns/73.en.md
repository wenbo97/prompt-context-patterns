> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

A deployment tool times out after accepting a release request.

## Mechanism

Stable action identity prevents ambiguous timeouts from duplicating effects.

## Bad example

```text
Retry deploy repeatedly until it returns success.
```

## Good example

```text
Persist release key r42 before submission. After timeout, query r42 status. Re-submit only through an idempotent API using the same key; advance submitted to healthy only after the recorded health check passes.
```

## Why the change matters

Stable action identity prevents ambiguous timeouts from duplicating effects.

## Observable expectation

Only one release is created for r42, and status reflects observed checks.

## Limits

The API must implement idempotency and concurrency control; prompts cannot supply them.  Separate an operation retry key from a source entity natural key. Repeated entity synchronization needs tenant-scoped destination uniqueness or native upsert; a natural key alone does not resolve uncertain write delivery. Reconcile unknown outcomes and reuse the receiver-enforced operation identity. For a user question, retry only a transport-confirmed pre-delivery failure; a question that may have appeared remains pending until an actual answer. No answer, a preselected default or elapsed time is not approval.
