> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

A browser extraction worked once and should become a reusable read-only tool.

## Mechanism

Preserve the successful command sequence and accepted input/output snapshot. Separate pure parsing from browser I/O, discard failed exploratory commands, and replay exact-value assertions before installing the procedure.

## Bad example

```text
Write a scraper from whatever you remember. Include all selectors tried; call it ready if it returns an object.
```

## Good example

```text
Codify the accepted extraction trace only. Keep the successful navigation sequence, isolate pure parsing, and replay the accepted HTML snapshot. Assert the expected item identities, order and fields against the accepted result. Install only after replay passes; record the snapshot date and live-site freshness separately.
```

## Why the change matters

A working trace is preserved as a reproducible procedure instead of a loose narrative and a shape-only smoke test.

## Observable expectation

Replay yields the accepted identities and field values; failed selector attempts do not appear in the installed procedure.

## Limits

Fixture success covers that snapshot, not future site HTML. Changed live input needs renewed validation; generated code and captured content remain untrusted until reviewed.
