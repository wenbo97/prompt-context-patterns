> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

A reviewer asks to remove a lock that appears unnecessary.

## Mechanism

A technical check distinguishes valid feedback from an unsupported preference.

## Bad example

```text
Agree immediately, remove the lock, and resolve the thread.
```

## Good example

```text
Read the referenced path and concurrent callers. If the lock protects a shared write, explain that evidence; if truly redundant, remove it and run the covering check. Record the decision and unresolved uncertainty before marking addressed.
```

## Why the change matters

A technical check distinguishes valid feedback from an unsupported preference.

## Observable expectation

Each response links a verified change or a reasoned dispute.

## Limits

Permission to fix code is not necessarily permission to post or resolve remote threads.
