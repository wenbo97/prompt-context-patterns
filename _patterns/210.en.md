> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

Refresh an already indexed list of recruiting candidates each day.

## Mechanism

Complete an initial snapshot, persist its sync token, request changes on the next run and apply additions/updates/deletions before advancing the token.

## Bad example

```text
Download every candidate daily and assume missing records were deleted.
```

## Good example

```text
Use the returned sync token to fetch changes; apply the documented change types; advance the checkpoint after successful processing.
```

## Why the change matters

Change APIs distinguish actual changes from omissions caused by pagination or permissions.

## Observable expectation

The next checkpoint follows applied changes and changed records retain their IDs.

## Limits

Handle expired tokens with a fresh snapshot; never advance beyond unprocessed changes.
