> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

Fix empty-email handling in a validator with unrelated username logic.

## Mechanism

Change the email defect, retain surrounding style and behavior, remove only newly unused code and report unrelated findings separately.

## Bad example

```text
Fix email handling while reformatting the whole file and tightening username policy.
```

## Good example

```text
Change the empty-email path; keep username rules and formatting; remove only the import made unused by this fix.
```

## Why the change matters

The diff preserves nearby behavior outside the authorized change.

## Observable expectation

Every changed line is explained by the request or a direct consequence of the fix.

## Limits

Necessary cross-file changes are allowed when causally required; this is a bounded-write rule, not a read-only prohibition.
