> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

A billing design uses customer, account and user inconsistently.

## Mechanism

A shared vocabulary exposes domain ambiguity instead of smoothing it away.

## Bad example

```text
Use account, customer and user interchangeably for readability.
```

## Good example

```text
Glossary: Customer owns the billing relationship; User is a login identity; Account is not a synonym for either. Use these terms in specs and examples; ask when 'account' appears without a defined meaning.
```

## Why the change matters

A shared vocabulary exposes domain ambiguity instead of smoothing it away.

## Observable expectation

Each occurrence can be checked against one canonical definition.

## Limits

Domain language can evolve; change the glossary explicitly rather than banning legitimate new concepts.
