> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

Add an export button to a production page.

## Mechanism

Keep per-task acceptance distinct from reusable quality/integration/operational gates and check both before completion.

## Bad example

```text
Declare done because the button downloads one file.
```

## Good example

```text
Confirm the requested export behavior, then check the accepted project bar for errors, accessibility, integration and required release evidence.
```

## Why the change matters

The procedure preserves the stated identity or evidence boundary instead of allowing a plausible shortcut to stand in for it.

## Observable expectation

A happy-path feature result does not conceal unmet readiness conditions.

## Limits

Tailor the standing bar to the actual project and authorized scope; this is different from #193 checkable-plus-exhaustive criteria.
