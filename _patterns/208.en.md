> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

Create a GIF for a channel with a known file-size limit.

## Mechanism

Generate, measure actual bytes/dimensions, report the failing constraint, adjust a relevant parameter and remeasure.

## Bad example

```text
Declare the GIF upload-ready because its animation looks good.
```

## Good example

```text
Measure the file; if over the known limit reduce frame count or palette; remeasure before reporting readiness.
```

## Why the change matters

Visual appeal alone does not establish technical deliverability.

## Observable expectation

The final report includes measured values and the limit used.

## Limits

Verify current platform constraints separately; this frozen source is not a current policy authority. For rendered exports, inspect the actual target-size output after fonts/images are ready, correct clipping and recapture. Measure exported pixel dimensions separately from CSS viewport size and device scale; elapsed delay alone does not prove asset readiness. Keep the requested platform constraint and checked file identities in the report.
