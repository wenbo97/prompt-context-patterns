> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

Repair a React confirmation dialog that fails to return keyboard focus to its opener after closing.

## Mechanism

Choose the smallest applicable search mode, express one intent with two to five terms, then verify the result's domain/category and top item's identity and applicability. Retry once when needed, label any fallback, and do not persist unverified output.

## Bad example

```text
Hypothetical catalog fixture: the same dialog issue yields style-pricing-palette from a broad search. Accept it solely because it mentions React and persist its palette as the fix without checking keyboard behavior.
```

## Good example

```text
Hypothetical catalog fixture: search "dialog keyboard focus" in UX mode. Check that ux-focus-return is accessibility guidance for restoring focus to the opener, with applicable platform scope. Query React implementation separately only if needed. Persist the checked guidance; if the bounded retry finds no suitable match, label fallback and retain no unverified result.
```

## Why the change matters

A concise query can still retrieve the wrong domain; checking both category and item fit catches that error before it becomes durable guidance.

## Observable expectation

The selected mode, query, top result, retry/fallback, and persistence decision can be inspected.

## Limits

This does not validate catalog accuracy or guarantee design quality. A failed search is not permission to invent a result; human review may still be needed. The two-to-five-term query and one-retry limit are bounded source-policy examples, not validated universal optima; choose terms and retry behavior by task, catalog, and freshness.
