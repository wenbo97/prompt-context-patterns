## Use case

Run a browser test that needs a frontend and backend server.

## Mechanism

Track started processes, bound readiness waiting, propagate the test result, and clean up in a finally block.

## Bad example

```text
Start servers and leave them running after a failed browser test.
```

## Good example

```text
Start both servers; wait within a timeout; run the test; preserve its exit status; stop owned servers on success or failure.
```

## Why the change matters

Task failure must not skip resource cleanup.

## Observable expectation

The command returns the test outcome and owned processes are terminated.

## Limits

A listening port does not prove application health; production helpers need stronger readiness and process-tree handling.
