> Independent teaching constructions, not observed model outputs or measured performance.

## Use case

Write an incident recommendation without generic filler advice.

## Mechanism

The prohibition names the unwanted output and supplies an actionable replacement.

## Bad example

```text
Write useful advice, be careful and do not make mistakes.
```

## Good example

```text
Do not recommend 'check your configuration' without naming a parameter and observed value. Cite the supplied config path. If the value is unknown, report that gap and name the next read instead of inventing a fix.
```

## Why the change matters

The prohibition names the unwanted output and supplies an actionable replacement.

## Observable expectation

Recommendations have concrete parameter evidence or an explicit missing-value check.

## Limits

Use constraints for observed failures; excessive bans can obscure the actual task.
