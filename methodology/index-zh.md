# 编辑标准与来源追溯

本站分别回答三个问题：方法是否适用于一个具体任务、原文实例在哪里，以及效果是否经过测量。

## 收录标准

每项缺失得0分，部分满足或较抽象得1分，具体完整得2分。收录要求总分至少8/10，且前三项各得2分。

| 标准 | 审核内容 |
| --- | --- |
| 使用场景 | 具体任务及已知条件 |
| 可操作机制 | 读者能执行的指令或操作 |
| 有效对照 | 同一任务、同一事实的 bad/good 示例 |
| 可检查结果 | 可观察的结果或工件 |
| 适用边界 | 需要调整或停止的条件 |

这是编辑标准，不是测得的成功概率。重复机制合并；薄弱或错误方法修订重评，或撤下。旧编号通过迁移页继续定位。

## 来源状态

已定位原文实例包含仓库、固定 commit、文件、小节和行范围。它证明某处存在该机制，不证明谁最早发明。最早出处另行记录。

**来源未确认**表示尚未定位原文。有用的方法仍须达到相同编辑标准，才能带着标签保留。找到引用并不能豁免错误建议，示例和事实主张仍须独立审核。

## 教学示例与实验

每个模式的正反例都是独立教学构造，不冒充历史模型输出。实际实验须说明样例、模型与配置、运行次数及可用输出。缺少原始输出的历史报告会明确标注，其数字不作为当前效果证据。
