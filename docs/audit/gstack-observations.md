# Gstack reading observations (working evidence)

Frozen repo: `garrytan/gstack` at `f30b7b788a210d217ea3125bf3001b29cbc2a463`. Research only; no source instructions or scripts were executed. Coverage remains in progress.

## Reading method

Heading blocks are read once for exact byte-identical occurrences. Skill-identity argument aliases are checked separately and retain occurrence locations. For near-identical blocks, every added and removed line is displayed against a previously read block; omitted lines must be exactly equal. `gstack-review-state.json` records the base and delta digest. A file closes only after every block is accounted for. Similarity selects a comparison base; it never establishes semantic equivalence or completion by itself.

## Methods and limits observed so far

- Review input snapshots, phase-local coverage, read-back before publication, accepted-obligation preservation and resume at the first incomplete gate appear in [autoplan](https://github.com/garrytan/gstack/blob/f30b7b788a210d217ea3125bf3001b29cbc2a463/autoplan/SKILL.md#L619-L746). Reading or hashing the snapshot does not prove semantic uptake. Freshness does not establish instruction authority.
- Scope decisions record current/proposed values and exact authorization in [CEO review](https://github.com/garrytan/gstack/blob/f30b7b788a210d217ea3125bf3001b29cbc2a463/plan-ceo-review/SKILL.md#L811-L1017). Review mode is distinct from approval of each scope change. Arbitrary file-count and effort thresholds are source heuristics, not universal quality measures.
- A potentially delivered question with no returned answer stays pending in [engineering review](https://github.com/garrytan/gstack/blob/f30b7b788a210d217ea3125bf3001b29cbc2a463/plan-eng-review/SKILL.md#L132-L155). Tool absence, transport failure, valid auto-decision and unanswered delivery have different outcomes.
- Explicit preferences and inferred observations are separated in [plan-tune](https://github.com/garrytan/gstack/blob/f30b7b788a210d217ea3125bf3001b29cbc2a463/plan-tune/SKILL.md#L603-L776). Profile floats and display gates are not validated psychometrics. A quote alone does not prove trusted user origin. Declined proposals lack durable dismissal in this version and can be repeatedly offered.
- Narrowing an existing agent's access revokes its prior grant in [pair-agent](https://github.com/garrytan/gstack/blob/f30b7b788a210d217ea3125bf3001b29cbc2a463/pair-agent/SKILL.md#L658-L689). This is a useful grant-lifecycle mechanism, subject to actual server enforcement. Expiry does not make a leaked live credential safe. JavaScript evaluation can reach data even when named cookie/storage commands are blocked.
- A context receipt needs project/branch identity and explicit stale status. A bounded search cannot prove no foreign candidate exists. Save filenames require atomic creation; checking existence and writing later leaves a race.
- Freeze hooks cover registered editor tools, not every shell write or an operating-system sandbox. A directory name is not deletion provenance. Guard text is not proof of hook registration.
- Investigation owns its cleanup with a token; replacing a guard means an earlier owner must not release the replacement. Reproduction should distinguish environment/data changes from code regressions. Three failed attempts do not prove the architecture is wrong, and green tests do not prove every bug is absent.
- Review findings require current bytes and relevant callers. A structural fingerprint is weaker than a content hash. Prior-commit comparisons can miss working-tree changes; being on the base branch does not imply no diff. Confidence labels are editorial judgments, not probabilities.
- Test-audit uses mutation-sensitive, independent behavioral oracles. Grep results and public-export absence are leads, not proof of dynamic unreachability. Time/scope limits must preserve partial coverage rather than declaring a full audit.
- Spec drafts require verified current state, observable criteria, boundaries and rollback. [Exact publication bytes are re-scanned](https://github.com/garrytan/gstack/blob/f30b7b788a210d217ea3125bf3001b29cbc2a463/spec/SKILL.md#L605-L620); a quality score does not waive the separate safety check. Unknown measurements stay unknown.
- Office-hours compares the problem, existing solutions and alternative approaches. Its private state directory is not automatically a cross-team shared space. Numeric founder signals do not establish likely startup success. Renderer/provider timing, cost and availability claims remain unverified source claims.
- DX review separates documented journeys, human measurements and automated timing, but its headline adoption multipliers and abandonment rates have no cited measurements. Roleplay timestamps are predictions rather than runtime evidence.
- Canary compares message identities and retains resolved incidents, but fixed two-round/2x thresholds are local heuristics. Identical counts can conceal new errors; an already unhealthy baseline does not become healthy merely by remaining unchanged. Local hostnames can proxy real side effects and do not grant mutation authority.
- Health capture preserves checker exit codes independently of parsers/tails and distinguishes capture failures from unavailable checks. The composite weights and score cutoffs are heuristic. Trend comparability also needs unchanged tools, fixtures and scoring definitions, not just identical check names.
- Shipping binds two reviews to the same working-tree content and inserts repairs before pending steps without resetting attempt budgets. Release reachability, revision deployment and target health are separate outcomes. Queue inspection is not an atomic version reservation. Its coauthor-trailer and host-plan-mode directives are not adopted.
- Setup-deploy prints four characters of a credential despite its secrecy rule; the improved examples never print any secret fragment. Piped status output can hide command failure without checking the producer's exit. Landing-report calls itself wholly read-only despite Git fetches, helper cache writes and fixed temporary-file output.
- CSO distinguishes supported static findings, external assertion witnesses, self-reported project-test completion and self-attested review. Target-controlled reporter output cannot establish authenticated completion; a second process is insufficient without a real trust boundary. Qualified profile/containment claims require helper implementation evidence and are not inferred from the skill text.
- Design-html's blanket layout-library recommendation is domain-specific; API sizes and universal benefits are unverified. Browser contenteditable edits are not automatically persisted into the source file. Design review's token whitelisting can conceal accessibility defects; a stored token is not an automatic waiver. Its bootstrap silently deletes failing tests and can revert unrelated manifest changes; those procedures are rejected rather than taught as safeguards. Page-count caps do not establish an exhaustive site audit.
- Skillify captures a successful trace and pure parser for replay, but fixture shape/nonempty assertions do not prove correct extraction. Freshly recaptured HTML may differ from the accepted run. Vendoring an SDK does not eliminate drift in the live server/site, and bounded recent-turn search is not complete history. Staged files did exist on disk before discard, so “nothing written” is a misleading literal claim; atomic publication depends on the helper. Its200ms prediction is not a measured guarantee.
- Document generation routes reader needs and maps changed public surface to documentation coverage. Fixed step/click limits are heuristics, not universal learning thresholds. Standalone publication/coauthor directives are not adopted. Delete-then-append report replacement is not atomic and can lose a prior report on interruption.
- Benchmark-models saves by rerunning the benchmark, which can charge again and save a different stochastic sample; serialize the original results instead. Provider auth markers are not successful calls, CLI harness overhead differs, and a single judge/model sample does not establish overall quality. Fixed cost claims are unverified.
- Browser benchmark calls transferSize a bundle-size measure despite cache/cross-origin zeroes and response compression. Its latest observed LCP may not be final; no CLS/INP data is actually collected in the displayed collection procedure. Network/session/cache/environment differences limit comparisons. Missing metrics remain unknown rather than zero.
- Open-gstack-browser kills a PID taken from writable state and deletes profile locks without checking active ownership; PID reuse can target another process. This conflicts with later live-daemon preservation rules and is rejected as cleanup guidance. Cookie counts/HTTP200 are not authentication proof; positive expected-identity evidence is a narrower useful check. An existing CDP connection alone does not prove the correct user is signed in.
- Tool-less external review appends a Git diff but omits untracked files and may use stale remote refs after suppressed fetch failures. Disabled tools do not automatically establish a full OS sandbox. Codex's IQ/disability persona stereotype and self-granted plan-mode exception are not adopted; harness identity and model identity remain distinct.
- Upgrade restoration claims need actual preserved input. Generated-looking paths can contain hand edits; checkout-before-autostash discards them. Migration selection lacks the documented upper-version bound. A responsive health endpoint does not prove a daemon is idle, and missing update-check output can mean failed execution rather than “latest”.
- iOS warm-start health alone does not verify device identity or schema compatibility. Fixture-driven state, visible provider UI and actual provider completion are distinct tiers. Snapshot restoration is not equivalent to replaying every external side effect. Schema mismatches should preserve original reproduction evidence; replacing it can erase the original regression. Build-artifact exclusion is stronger than a cleanup reminder, but requires actual compiler/link evidence.
- Retrospective commit gaps, LOC and directory churn are proxies, not measured working time, impact or focus. Inactivity is valid data rather than proof of a stale ref. Git identity is not necessarily the report reader. Same-window history still needs comparable authors/ref/filter definitions. Fixed founder-signal rankings and discomfort/forced-certainty coaching are not validated inference.
- Setup-gbrain treats a local engine as personal by default and can flip an explicit off sync setting to full; locality does not prove single tenancy or permission to publish. Name-prefix orphan detection is not resource ownership proof. Timeout is unknown, not healthy. Its smoke procedure does not show the deletion claimed by the final template. Sync status and source-scoped page-read success do not prove semantic search or edge availability. Fixed temporary filenames and age-only stale-lock takeover need stronger ownership/concurrency checks.
- Plan review combines overlapping awaits into one shared-state schedule and exercises both relevant completion orders; separate diagrams and atomic assignments do not prove asynchronous ordering. The tasks aggregator filters by five commits and title/files/component, which can omit a current uncommitted review or collapse distinct obligations; matching labels need semantic reconciliation and preserved provenance. Prior findings shown to only one design reviewer create intentionally different context and limit independence/consensus interpretation.
- Confidence quotation is useful evidence but not proof: an empty initialized dictionary does not establish a later key/value invariant, and merely finding a metaclass construct does not validate every generated symbol. Fixed confidence bands, lake scores and human/agent effort multipliers are heuristics. Hall-of-Fame adoption/performance percentages and blanket product/API claims lack supporting primary measurements and are not propagated as facts. Partial30KB review input cannot justify full coverage; an empty task file cannot identify the latest zero-task run when aggregation examines records only.
- QA reporting separates observed channel, expectation, confirmation and causal hypothesis; every summary and proposed assertion must preserve that boundary. A console message is not an uncaught exception, one observation is not recurrence, and guard durations are not component latency or complete session time. A record written after the fact is not a contemporaneous probe checkpoint. The deadline helper's own receipt is not the observed child result.
- Codex streaming parsers print failed/missing terminal events without necessarily making their own exit nonzero, swallow malformed JSON, and save a started session ID before verified completion. Review's severity-substring gate can count quoted examples instead of actual findings; output must be interpreted with its completion/coverage limits. Inline user text in double-quoted shell assignments is unsafe; fixed diff delimiters are labels rather than containment.

## Generator, host and hook contracts

The full prompt resolver bodies, all host definitions and hooks, careful/freeze scripts, Autoplan publication hook, explicit preference writer and skill-start/end instruction emission were read as source data. A tool rename does not prove identical permission, process, persistence or asynchronous semantics. Claude lazy sections and other hosts' inline bodies have different context costs; QA retains lazy sections on all hosts. A front-matter allowlist should retain only fields actually consumed by its target host, with unavailable required assets reported as coverage gaps.
- AUQ hooks separate transport failure from a delivered but unanswered question and keep unknown answers explicit. Their conservative parsing is useful, but a textual source label or environment-driven spawned marker is not authenticated human consent. The main preference hook's unknown-ID classifier checks question text, whereas its spawned branch also checks options; neither keyword classification nor a stale registry guarantees every one-way effect is recognized. - The memory bridge bounds inputs and scan traversal, preserves UTF-8 boundaries, limits inherited environment, records a pre-send receipt and reports missing outcomes as unknown. A local-binary receipt cannot establish that binary's later network behavior. Process-group cleanup does not contain descendants that deliberately create another session. The synchronous secret scan's size allowance estimates runtime; it cannot preempt a stalled scan or prove all secrets are detected. Prefix filtering does not prove semantic privacy.
- The timeline Stop hook explicitly closes every project's dangling start with outcome unknown, including another live session. That record must not be treated as actual task completion. Bounded tail inspection and append-only storage do not guarantee ownership or concurrent idempotency. The skill-start pending-file cleanup likewise relies on local conventions rather than run ownership.
- Careful's string matching is expressly an advisory tripwire, not shell enforcement. Freeze checks selected file tools and follows existing symlinks, but non-file shell tools bypass it; path changes between check and write remain possible, and a nonexistent parent cannot supply a canonical physical path. The owned freeze mutation token/mutex prevents ordinary accidental release of another run's replacement state; it is not an access-control boundary.
- Autoplan's native publication hook binds known Read/Agent events to invocation artifacts and verifies delivered line ranges, ordered close packets, unchanged accepted obligations and parent-visible reporting. - Source-specific shortcuts remain visible: plan completion caps fifty items, cross-repo file existence is weaker than required behavior, some percentage/rating failures skip gates, some bootstrap paths delete valid red tests, and the task aggregator cannot identify a new empty run from old nonempty JSONL records.
